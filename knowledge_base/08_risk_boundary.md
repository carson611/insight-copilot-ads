# 08 风险与边界

## KB-RISK-001 幻觉控制

- 适用问题：所有 AI 分析回答。
- 触发词：原因、为什么、归因、建议、结论。
- 控制原则：
  1. 只能基于当前筛选数据、规则层结果和 RAG 知识卡回答。
  2. 知识卡只提供分析框架和常见假设，不代表当前业务事实。
  3. 不能虚构真实业务动作，例如换素材、改价格、缺货、页面故障。
  4. 原因必须写成“可能原因”或“待验证假设”。
  5. 如果数据不支持判断，要明确说明需要补充字段。
- 推荐表达：
  - “从当前数据看，可能与...有关。”
  - “该判断还需要结合...进一步验证。”
  - “当前数据只能定位异常维度，不能确认真实业务原因。”
- 禁止表达：
  - “原因一定是...”
  - “已经证明...”
  - “上线后提升了...”

## KB-RISK-002 图表生成边界

- 适用问题：图表证据、图表计划、可视化分析。
- 触发词：画图、图表、证据、可视化。
- 控制原则：
  1. LLM 不直接生成图表代码并执行。
  2. 图表计划由系统内部根据问题意图和字段能力生成，不在前台展示。
  3. 系统必须校验指标、维度、图表类型和字段权限。
  4. 校验通过后，由 Plotly 基于真实数据渲染图表。
  5. LLM 只引用和解释图表证据，不输出图表 JSON、图表代码或伪图表。
  6. 周报正文只输出文字，图表统一由系统下方独立板块展示。
- 推荐表达：
  - “图表由系统基于当前数据实时渲染。”
  - “LLM 负责选择和解释证据，不负责凭空画图。”
- 风险边界：不能展示与当前筛选数据不一致的图表。

## KB-RISK-003 数据安全

- 适用问题：上传数据、API 调用、隐私字段。
- 触发词：上传、权限、隐私、安全、API、脱敏。
- 控制原则：
  1. 本地 Demo 优先本地处理上传数据。
  2. 调用 LLM 时只传聚合摘要、指标结果、知识卡和字段说明，尽量不传原始明细。
  3. 对用户 ID、手机号、姓名、地址等字段做脱敏或禁止上传。
  4. 产品方案中要提供字段权限和角色权限设计。
- 推荐表达：
  - “当前 Demo 不上传敏感个人字段。”
  - “接入生产系统时需增加字段级权限、脱敏和审计。”
- 风险边界：不能承诺企业级安全合规已完成。

## KB-RISK-004 指标口径一致

- 适用问题：指标解释、周报、看板、问答。
- 触发词：口径、指标、定义、计算、为什么不一样。
- 控制原则：
  1. 所有回答必须使用同一套指标字典。
  2. 同名指标不能混用不同口径。
  3. 周报、看板和 Copilot 问答要引用同一计算函数。
  4. 需要展示指标解释和字段映射结果。
  5. 上传字段与标准字段不一致时，先做字段映射确认再分析。
- 推荐表达：
  - “本报告中的 ROI = GMV / 广告消耗。”
  - “下单转化率 = 支付订单量 / 注册量。”
- 风险边界：若用户上传字段口径不一致，需要先提示确认，不能直接分析。

## KB-RISK-005 项目简历表达边界

- 适用问题：简历、面试、作品集。
- 触发词：简历、面试、项目成果、上线、提升。
- 控制原则：
  1. 未真实上线不能写上线数据。
  2. 没有真实用户数据不能写用户规模。
  3. Demo 阶段可以写“完成本地可演示 Demo”。
  4. 用户测试阶段可以写“基于测试反馈优化交互和回答质量”，但不能编造转化提升。
- 推荐表达：
  - “完成电商广告投放复盘 Copilot 本地 Demo。”
  - “设计指标计算、RAG 知识增强、图表计划和幻觉控制方案。”
  - “基于测试反馈迭代问题识别和图表证据展示。”
- 风险边界：不要写“提升 ROI xx%”“服务 xx 用户”等虚构结果。
