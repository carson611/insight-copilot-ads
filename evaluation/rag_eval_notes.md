# Insight Copilot for Ads RAG 评估说明 v0.1

## 评估目标

RAG 接入后，需要验证它是否真的提升了电商广告分析回答质量，而不是只在页面上展示“调用了知识库”。

当前评估关注四件事：

1. 意图识别是否正确：自然语言问题能否映射到转化、ROI、成本、收入、预算、周报等意图。
2. 知识卡召回是否相关：问题能否召回对应诊断框架、指标口径、图表规则和风险边界。
3. 回答是否更专业：回答是否包含电商广告分析路径，而不是泛泛总结。
4. 风险是否受控：模型是否避免虚构真实业务原因、上线效果、用户规模或图表。

## 首轮评估结果

2026-08-27，用户已完成 15 条典型问题的人工评估，当前状态均标记为“通过”。该结论基于 Demo 实测体验，用于说明 RAG v0.1 在当前样例数据和核心问题集上已达到可演示标准。

## 当前评估方式

第一版采用人工评估，不做自动打分。原因是当前样例数据较小，且回答质量需要判断业务表达是否合理。

评估文件：

- `evaluation/rag_eval_cases.csv`：测试问题集。
- `knowledge_base/*.md`：RAG 知识卡来源。

每条 case 记录：

- 用户问题
- 期望意图
- 期望召回知识卡
- 期望图表
- 回答中应该包含的要点
- 回答中必须避免的风险

## 人工评分标准

每条问题建议按 1-5 分评价。

### 1. 意图识别

- 5 分：意图完全正确，图表证据方向匹配。
- 3 分：大方向正确，但细分意图有偏差。
- 1 分：意图错误，导致图表和回答明显不匹配。

### 2. 知识召回

- 5 分：召回了最相关的诊断框架、指标卡和图表规则。
- 3 分：召回部分相关知识，但缺少关键卡片。
- 1 分：召回内容与问题关系弱。

### 3. 回答质量

- 5 分：结论清晰，证据充分，分析路径专业，动作建议可执行。
- 3 分：基本回答问题，但分析路径或动作建议较泛。
- 1 分：大段空话，缺少指标证据或业务判断。

### 4. 风险控制

- 5 分：明确区分数据事实、可能原因和待验证假设。
- 3 分：偶尔表达偏确定，但未出现严重虚构。
- 1 分：虚构真实业务原因、上线效果、用户规模或图表。

## 期望优化方向

### v0.1 关键词 RAG

当前版本使用关键词和意图词典检索知识卡，优点是简单、可控、便于解释；缺点是对复杂语义和同义表达覆盖有限。

### v0.2 图表计划 JSON

下一步让 LLM 输出结构化图表计划，例如：

```json
{
  "intent": "roi_analysis",
  "charts": [
    {
      "chart_type": "bar",
      "metric": "roi",
      "dimension": "channel",
      "sort": "ascending",
      "title": "渠道 ROI 对比"
    }
  ]
}
```

系统校验字段、指标、维度和图表类型后，再用 Plotly 渲染真实图表。

### v0.3 向量检索

当知识库扩展到 100 张以上卡片时，可以引入 embedding + FAISS / Chroma，提高同义问题和长问题的召回能力。

### v0.4 样本沉淀与微调评估

收集用户问题、RAG 召回结果、图表计划、人工修正回答，沉淀为训练样本。只有当样本达到 50-100 条且稳定复现问题后，再评估是否微调。

## 面试讲法

可以这样描述：

> 我没有简单把用户问题直接丢给大模型，而是设计了一个 RAG 增强链路。系统会先识别问题意图，从电商广告分析知识库中检索指标口径、诊断框架、图表选择规则和风险边界，再结合 pandas 计算出的真实指标和 Plotly 渲染的真实图表，让 LLM 生成业务复盘回答。为了验证 RAG 不是摆设，我设计了 15 条典型问题评估集，从意图识别、知识召回、回答质量和风险控制四个维度做人工评估。

## 当前限制

- 当前评估为人工评估，尚未做自动评分。
- 当前 RAG 是关键词检索，尚未接入 embedding。
- 当前知识库来自公开口径和项目分析框架整理，尚未接入真实企业内部知识。
- 当前样例数据为模拟电商广告数据，不能声称真实业务效果提升。
