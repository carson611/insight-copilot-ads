# Insight Copilot Demo 说明文档（v1.2 暂定版）

## 一、项目定位

Insight Copilot / AI 数据分析 Copilot 是一个面向产品经理、运营和业务同学的数据分析助手 Demo。

用户可以读取系统样例数据，或上传自己的 CSV / Excel 表格，通过自然语言式问题入口查看指标看板、趋势图、异常归因和业务周报摘要。

这个项目的核心定位不是算法研究，也不是训练大模型，而是一个产品经理视角的 AI 产品项目：用可演示 Demo 证明自己能把用户场景、数据指标、AI 交互、风险边界和产品迭代串成完整闭环。

## 二、v1.2 版本目标

v1.2 暂定为“数据接入与字段适配版”。

本版本重点解决三个问题：

1. 用户不一定使用系统预设字段名，上传数据后需要字段映射。
2. 单一渠道分析不够，需要支持品类、广告类型、活动类型等多维分析。
3. 字段映射区过长会影响筛选体验，确认后应该自动收起。

## 三、当前已实现功能

| 模块 | 已实现能力 | v1.2 说明 |
| --- | --- | --- |
| 数据源管理 | 支持样例数据、CSV 上传、Excel 上传、上传历史选择 | 上传历史为本次会话级，最多保留最近 5 个文件 |
| 字段映射 | 上传后自动推荐字段映射，支持用户手动调整 | 必填字段未完成时不进入上传数据分析 |
| 映射确认交互 | 字段映射区尾部增加“确认字段映射”按钮 | 点击确认后映射区自动收起，只保留“字段映射已确认”和“重新映射” |
| 指标看板 | 展示收入、订单量、下单转化率、ROI、成本等核心指标 | 支持本周 vs 上周对比 |
| 趋势图表 | 展示转化率趋势、渠道 ROI、周期对比等图表 | 用于支撑业务判断，而不是单纯展示图 |
| 多维透视 | 支持渠道、地区、设备、商品品类、广告类型、活动类型分析 | 可选择收入、订单量、成本、下单转化率、ROI |
| Copilot 问答 | 支持固定业务问题和规则化业务解释 | 当前是规则问答 + 指标计算，尚未接入真实 LLM API |
| 周报摘要 | 支持选择自然周并生成业务周报草稿 | 输出基于当前筛选数据和固定指标口径 |
| 产品边界 | 展示 AI 错答、幻觉、权限、数据安全、指标口径等方案 | 为后续面试追问预留产品设计空间 |

## 五、当前支持的问题

Copilot 问答区当前支持：

1. 本周转化率为什么下降？
2. 哪个渠道 ROI 最差？
3. 哪个渠道拖累最大？
4. 本周收入为什么下降？
5. 投放成本为什么上涨？
6. 哪个渠道最值得加预算？
7. 哪个品类拖累最大？
8. 哪种广告类型 ROI 最差？
9. 哪个活动类型表现最好？
10. 帮我给老板写三条业务结论
11. 帮我生成一份业务周报

## 六、推荐演示路径

面试或作品集演示时，建议按下面顺序讲：

1. 打开 Insight Copilot 本地页面。
2. 先展示样例数据下的指标看板，说明这是电商增长分析场景。
3. 展示本周 vs 上周核心指标对比，引出“转化率下降”问题。
4. 在 Copilot 问答区选择“本周转化率为什么下降？”。
5. 展示系统输出的结论、关键证据和建议动作。
6. 切到多维透视，选择商品品类、广告类型或活动类型，说明 v1.2 支持更细归因。
7. 上传 `ecommerce_growth_user_upload_test.csv`，展示字段自动推荐和手动映射。
8. 点击“确认字段映射”，说明确认后映射区会自动收起，筛选区回到高频操作位置。
9. 进入周报摘要页，选择自然周并生成业务周报草稿。
10. 最后说明当前边界和 v2 规划，包括真实 LLM API、权限、脱敏、置信度和用户反馈闭环。

## 八、验证结果

当前已完成基础验证：

- `app.py` 语法编译通过。
- 本地 Streamlit 页面可访问。
- 测试上传文件可通过字段映射生成标准分析数据。
- 测试上传文件映射后共有 1680 行。
- 系统可自动补充 `week_label`，并计算 CTR、注册转化率、下单转化率、ROI、客单价等派生指标。

样例数据中的业务现象：

- 本周下单转化率较上周下降。
- 抖音是转化下降的主要拖累渠道。
- 搜索广告 ROI 最差。
- 美妆个护、直播带货等维度可用于更细归因。

以上均为样例数据和本地 Demo 验证结果，不代表真实上线数据或真实业务增长结果。

## 九、当前边界

v1.2 仍然不是完整 AI 版本。

当前问答能力主要来自规则识别、指标计算和固定解释模板。字段映射以别名匹配和用户手动确认为主，还没有做真正的语义理解。上传历史为本地会话级，不是账号级数据资产管理。权限、脱敏、指标口径审批、SQL 白名单和结果置信度目前是产品方案层设计，尚未完整工程化。

面试中应诚实表达：

“我先用规则和指标计算实现 MVP，验证业务分析链路和用户交互闭环。v1.2 重点补了用户上传数据后的字段适配、多维归因和映射确认体验。后续如果接入大模型，会重点补充意图识别、口径引用、SQL 生成、权限控制、数据脱敏和结果置信度机制。”

## 十、下一步计划

v1.2 暂定完成后，建议先找同学、实习同事或产品方向朋友做小范围体验，收集反馈后再进入 v2。

用户测试重点：

- 用户是否知道该上传什么数据。
- 字段映射是否容易理解。
- 上传失败时是否知道怎么修。
- 多维透视是否能帮助定位问题。
- 哪些问题最需要真正自然语言问答。
- 哪些回答需要大模型润色或解释。

v2 暂定方向：

- 接入真实 LLM API。
- 支持自由提问和意图识别。
- 增加结果置信度和引用指标口径。
- 增加数据脱敏、权限控制和敏感字段提示。
- 整理作品集 PPT / PDF，包括背景、需求、PRD、原型、Demo、复盘和面试讲述稿。
