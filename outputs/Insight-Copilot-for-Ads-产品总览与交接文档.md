## 3. PRD 总结

### 3.1 项目背景

在小米中台数据产品实习和一视科技产品经理实习中，我观察到一个共性问题：产品、运营和业务同学经常需要基于数据做判断，但从数据到结论的链路比较重。

典型链路包括：

1. 获取数据
2. 确认指标口径
3. 查看 BI 看板
4. 按维度拆解
5. 解释异常变化
6. 整理复盘结论
7. 写入周报或汇报材料

即使已经有 BI 看板，很多业务用户依然会卡在：

- 为什么变了？
- 哪个渠道拖累最大？
- 哪个广告类型 ROI 最差？
- 下周应该先看哪里？
- 这段结论怎么写进周报？

Insight Copilot for Ads 希望解决的不是“替代数据分析师”，而是降低产品 / 运营 / 投放同学完成广告投放复盘和基础数据分析的门槛。

### 3.2 问题定义

| 问题 | 用户表现 | 产品机会 |
| --- | --- | --- |
| 分析链路重 | 临时分析需求需要反复处理 Excel 或找数据同学 | 用样例数据 / 上传数据 + Copilot 问答降低启动成本 |
| 指标口径不清 | 看到转化率、ROI，但不确定计算公式和数据范围 | 每次输出绑定指标公式、数据范围和字段来源 |
| 异常难解释 | 知道本周转化率下降，但不知道从哪个维度下钻 | 提供本周 vs 上周对比和维度拆解 |
| 投放决策不直观 | 不知道哪个渠道浪费预算，哪个渠道值得加码 | 通过 ROI、GMV、广告消耗、转化率综合判断 |
| 周报写作耗时 | 周报容易停留在描述数据，缺少结构化结论 | 按固定结构生成投放周报草稿 |
| AI 结论不可信 | 担心 AI 编造原因或把相关性说成因果 | 区分数据事实、分析推断和行动建议，并展示风险提示 |

### 3.3 产品目标

1. 让产品经理、运营和投放同学能用低门槛方式完成电商广告投放复盘。
2. 让每个分析结论尽量绑定图表、指标口径、数据范围和关键证据。
3. 支持转化率波动、渠道 ROI、广告消耗、品类拖累、活动表现、周报生成等高频场景。
4. 在产品方案中体现 AI 错答、幻觉、权限和数据安全治理意识。
5. 形成一套可写进简历、可进入面试讲述的 AI 产品项目材料。

### 3.4 本阶段非目标

1. 不训练大模型，不做算法研究。
2. 不接入公司真实数据，不复刻任何公司内部系统。
3. 不虚构上线数据或业务增长结果。
4. 不做完整企业级 BI 平台。
5. 不做复杂因果推断，当前只做基于样例数据的波动拆解和可能原因提示。
6. 当前暂不接入真实 LLM API，先用规则识别 + 指标计算 + 模板输出保证 Demo 稳定。

### 3.5 目标用户

| 用户 | 典型任务 | 核心痛点 | 项目价值 |
| --- | --- | --- | --- |
| 产品经理 | 看功能效果、转化漏斗、活动效果，准备复盘材料 | 临时分析多，依赖数据同学，异常后不知道怎么拆 | 快速获得指标解释、图表和异常拆解方向 |
| 运营同学 | 分析渠道 ROI、活动效果、转化路径和周报 | Excel 处理费时，周报重复劳动多 | 快速找出差渠道，生成结构化周报草稿 |
| 投放同学 | 看广告消耗、ROI、渠道质量、素材 / 活动效果 | 需要快速判断预算浪费点和加码点 | 输出渠道 / 广告类型 / 活动类型层面的投放建议 |
| 业务负责人 | 看本周业务变化、风险点和建议动作 | 不想看复杂明细表，只关心结论和依据 | 获得摘要、关键异常和可追问线索 |

## 4. 低保真原型总结

### 4.1 原型目标

低保真原型的目标不是做漂亮 UI，而是把用户从“选择数据”到“生成投放周报”的路径画清楚。

原型要回答：

- 用户从哪里开始？
- 用户怎么上传或选择数据？
- 用户怎么提问？
- 系统怎么给结果？
- 异常怎么继续拆解？
- 最终产出如何进入真实工作流？

### 4.2 用户主流程

当前主路径：

1. 进入 Insight Copilot for Ads
2. 查看电商广告样例数据
3. 浏览投放看板
4. 发现本周下单转化率 / ROI / GMV 异常
5. 进入投放 Copilot
6. 选择广告投放复盘问题
7. 系统输出结论、关键证据和投放动作建议
8. 进入多维透视，看渠道 / 品类 / 广告类型 / 活动类型
9. 上传测试文件并完成字段映射
10. 生成广告投放周报草稿

### 4.3 信息架构

当前 Demo 对应 4 个核心模块：

| 模块 | 用户目的 | 核心信息 |
| --- | --- | --- |
| 投放数据与筛选 | 让用户把可分析的数据放进系统 | 样例数据、上传文件、上传历史、字段映射、日期 / 渠道 / 设备 / 地区筛选 |
| 投放看板 | 让用户快速看到整体广告投放表现 | KPI 卡、趋势图、渠道 ROI、核心指标对比、渠道归因、多周趋势、维度透视 |
| 投放 Copilot | 让用户用问题入口完成复盘分析 | 推荐问题、自由输入、分析结论、关键证据、投放动作建议 |
| 投放周报 | 让用户把分析结论转成可复用汇报草稿 | 周期选择、一键生成、结构化周报文本 |
| 数据口径 | 让用户理解字段和指标公式 | 当前支持字段、数据预览、AI 产品边界 |

### 4.4 原型页面说明

页面 1：投放数据与筛选

- 上传广告投放 CSV / Excel
- 选择电商广告样例数据或上传历史
- 字段映射确认
- 确认后自动收起字段映射区
- 支持重新映射
- 日期范围筛选
- 渠道、设备、地区、商品品类、广告类型、活动类型筛选

页面 2：投放看板

- GMV、支付订单量、下单转化率、ROI、广告消耗 KPI
- 下单转化率趋势
- 渠道 ROI 对比
- 本周 vs 上周核心指标表
- 渠道归因拆解
- 多周趋势
- 维度透视分析

页面 3：投放 Copilot

- 选择广告投放复盘问题
- 支持手动输入问题
- 输出 AI 投放分析提示
- 输出结论
- 输出关键证据
- 输出投放动作建议

页面 4：投放周报

- 选择自然周
- 点击生成投放周报
- 输出投放周报草稿
- 当前为文本草稿，后续可做复制、导出、结构化编辑

页面 5：数据口径

- 展示当前筛选后数据行数和日期范围
- 展示字段字典
- 展示样例数据预览
- 展示 AI 错答 / 幻觉 / 权限 / 数据安全 / 指标口径方案

## 7. AI 产品方案与边界

### 7.1 当前 AI 能力

当前 Demo 的 AI 能力是“规则问答 + 指标计算 + 模板化解释”。

它可以：

- 根据问题关键词识别分析意图
- 计算指标
- 找出变化最大的渠道 / 维度
- 输出结论、证据和建议
- 生成周报草稿

它还不能：

- 真正理解任意自然语言问题
- 自动识别任意行业字段语义
- 连接真实数据库生成 SQL
- 做企业级权限控制
- 给出严格因果推断
- 处理复杂多表 join

### 7.2 为什么暂时不接 API

当前阶段优先做产品闭环，而不是为了“用了大模型”而接 API。

原因：

1. Demo 首先要稳定，规则问答可以保证演示结果可控。
2. 当前样例数据和问题模板已经能验证核心流程。
3. 用户测试前贸然接 API，可能增加成本和不稳定性。
4. 接 API 后必须补权限、脱敏、口径引用、置信度和人工确认机制，否则面试被追问会很危险。

### 7.3 后续接入 LLM API 的产品方案

v2 可考虑在以下位置接入 LLM：

1. 用户意图识别：把自由问题解析为指标、维度、时间范围。
2. 解释润色：把规则计算结果转成更自然的业务语言。
3. 周报生成：基于固定结构生成更完整的复盘报告。
4. 异常假设生成：基于数据现象提出可能原因，但必须区分事实和推断。

必须配套的产品机制：

- 指标口径引用
- 数据范围引用
- 低置信度提示
- 敏感字段识别
- 上传数据脱敏
- 权限控制
- SQL 白名单
- 人工确认机制

### 10.2 1 分钟项目介绍

我做了一个叫 Insight Copilot for Ads 的个人项目，定位是面向产品经理、运营和投放同学的电商广告投放效果分析 Copilot。

所以我没有直接做一个泛泛的聊天机器人，而是聚焦电商广告投放复盘，做了一个本地可演示 Demo。用户可以读取样例数据或上传 CSV / Excel，通过字段映射接入数据，然后在投放看板里看 GMV、广告消耗、ROI、转化率等指标，也可以在 Copilot 里问“本周广告投放转化率为什么下降”“哪个渠道 ROI 最差”，系统会输出关键证据和投放动作建议，最后还能生成广告投放周报草稿。

当前版本没有接入真实大模型 API，主要用规则识别和指标计算保证结果稳定。后续如果接入 LLM，我会重点补意图识别、口径引用、数据脱敏、权限控制和结果置信度机制。

如果只是让 Codex 生成一个数据看板页面，确实成本更低。但我的项目重点不是“生成代码”，而是用产品经理视角沉淀一个具体业务场景的标准分析流程。

Insight Copilot for Ads 聚焦电商广告投放复盘，核心链路是：数据接入 -> 字段映射 -> 指标看板 -> 异常识别 -> 维度归因 -> 投放动作建议 -> 周报草稿。

- 有固定字段字典和指标口径，避免每次临时解释。

- 有渠道、品类、广告类型、活动类型等投放维度。
- 输出会区分数据事实、关键证据和投放建议。
- 后续规划了权限、脱敏、置信度和口径引用，而不是直接让 AI 自由发挥。

所以我想体现的是产品经理对场景、流程、边界和迭代的设计能力，而不是单纯展示一个页面。

把当前偏简单的 Streamlit UI 改成更像“广告投放周复盘工作台”的界面。

优先做：

1. 首页新增“本周异常摘要”。
2. 把 KPI 区改成更清晰的投放指标组。
3. 增加“复盘流程引导”：先看异常、再看归因、再看建议、最后生成周报。
4. 优化图表布局和标题，让页面更有业务语境。
5. 增加上传空状态和字段示例。

合格标准：

别人打开页面后，不需要解释太多，就能知道这是广告投放复盘工具，并且能按页面路径完成一次复盘。

### 12.2 v1.4：归因能力增强

目标：

把当前维度排序升级为更强的投放分析链路。

优先做：

- 曝光 -> 点击 -> 注册 -> 下单 -> ROI 链路拆解
- 区分流量问题、点击问题、注册问题、下单问题、成本问题
- 输出更明确的异常类型
- 输出更像投放复盘的动作建议

### 12.3 v2：真实 LLM API（已进入当前 Demo）

触发条件：

用户测试表明固定问题模板不够用，用户确实需要自由提问和更自然的解释。

v2 方向：

- 接入 LLM API
- 意图识别
- 结果润色
- 周报增强
- 置信度
- 口径引用
- 脱敏和权限

### 12.4 v3.0-v3.1：指标系统建设

当前判断：

用户自然语言问题会不断出现广告专业指标。如果系统没有提前注册指标公式、字段依赖和图表证据，LLM 即使知道指标定义，也无法稳定基于真实数据分析。

v3.0 方向：

- 建立指标注册中心
- 管理指标公式、字段依赖、格式化方式和正负向含义
- 将指标注册中心打通看板、Copilot、RAG 和图表计划
- 已接入 CPC、CPA、CPM、单订单成本、CVR 和贡献占比
- 后续迭代可继续补 CPL、退款率、复购率、CAC、LTV、LTV/CAC 等更高级指标

### 12.5 作品集方向

作品集建议结构：

1. 项目背景：为什么做
2. 目标用户：产品经理 / 运营 / 投放同学
3. 需求洞察：从实习观察和用户反馈出发
4. PRD：目标、非目标、用户故事、功能优先级
5. 原型：用户路径和页面结构
6. 数据：样例数据、字段字典、指标口径
7. Demo：页面截图、核心功能
8. 迭代：v1.1、v1.2、v1.3、v2、v3.0
9. AI 产品边界：错答、幻觉、权限、数据安全
10. 复盘：做对了什么、当前不足、下一步

## 13. 当前最重要的产品判断

目前最重要的判断是：

不要把它包装成泛泛的 AI 数据分析助手。

它应该被包装成：

> 一个面向电商广告投放复盘的垂直 Copilot。

这样才能解释清楚：

- 为什么字段是这些字段
- 为什么问题是这些问题
- 为什么样例数据是电商广告投放数据
- 为什么当前不支持任意行业数据
- 为什么它和直接让 Codex 生成页面不一样
- 为什么它对产品经理秋招有价值

后续所有功能和 UI，都应围绕“广告投放周复盘”这个场景继续收敛。
