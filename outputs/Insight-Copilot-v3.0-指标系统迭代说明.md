# Insight Copilot v3.0 指标系统迭代说明

## 版本命名约定

从当前阶段开始，Insight Copilot for Ads 的版本线调整为：

| 版本 | 阶段定位 | 说明 |
|---|---|---|
| v1.x | 本地 Demo 与垂直定位阶段 | 完成样例数据、上传映射、规则诊断、周报草稿和电商广告垂直定位。 |
| v2.0 | AI Copilot 阶段 | 接入 DeepSeek API、RAG 知识库、隐藏图表计划、AI 问答和 AI 周报生成。 |
| v3.0 | 指标系统建设阶段 | 从“写死少量二级指标”升级为可扩展指标体系，让指标计算、图表证据、RAG 知识和自然语言问题识别保持一致。 |
| v3.1+ | 指标系统小版本迭代 | 在 v3.0 基础上继续补充指标、公式、口径、证据表、异常规则和测试用例。 |

## 为什么进入 v3.0

当前 Demo 已经具备 AI 问答和 RAG 增强能力，但暴露出一个关键产品问题：

用户自然语言提问可能涉及大量电商广告专业指标，例如 CPC、CPM、CPA、CVR、AOV、CAC、LTV、退款率、复购率等。如果系统没有提前计算和注册这些指标，LLM 即使知道定义，也无法稳定调用真实数据生成正确分析。

因此 v3.0 不再只追求“让 AI 多知道一些知识”，而是建设一套指标系统：

数据字段 -> 派生指标计算 -> 指标元信息 -> 问题意图识别 -> 图表证据 -> RAG 解释 -> AI 输出。

## 产品原则

1. 指标计算由代码和规则层完成，不能依赖 LLM 临场计算。
2. RAG 知识库负责解释指标口径、诊断路径、常见假设和风险边界。
3. LLM 负责组织表达、引用证据和生成可读结论，不负责凭空算数。
4. 用户问到未注册指标时，应提示缺少指标口径或必要字段，而不是硬编。
5. 每个新增指标必须同时补齐：公式、字段依赖、格式化方式、推荐图表、风险边界和测试问题。

## v3.0 已完成内容

### 1. 新增成本效率类派生指标

| 指标 | 公式 | 所需字段 | 当前状态 |
|---|---|---|---|
| CPC | 广告消耗 / 点击量 | cost, clicks | 已接入 |
| CPM | 广告消耗 / 曝光量 * 1000 | cost, impressions | 已接入 |
| 单订单成本 | 广告消耗 / 支付订单量 | cost, orders | 已接入 |

### 2. 已接入产品链路

- 看板 KPI 新增 CPC。
- 多周趋势支持选择 CPC、CPM、单订单成本。
- 维度透视支持按渠道、地区、设备、品类、广告类型、活动类型分析成本效率指标。
- Copilot 能识别 “CPC 为什么上涨”“哪个渠道 CPC 最高”“CPM 为什么变高”“单订单成本哪个渠道最高”。
- 图表证据新增 CPC / CPM / 单订单成本趋势图、渠道排行图和证据明细表。
- RAG 知识库新增 CPC、CPM、单订单成本指标卡和 CPC 成本效率诊断卡。

## v3.0 当前边界

当前成本效率类指标仍基于广告投放明细聚合计算，不包含：

- 平台出价
- 关键词竞价环境
- 广告位
- 素材粒度
- 人群包
- 频控
- 用户级 CAC / LTV

因此可以判断“CPC 是否上涨、哪个渠道 CPC 高、成本和点击量如何共同影响 CPC”，但不能确认“CPC 上涨一定来自出价上涨或竞争加剧”。

## v3.1 建议方向

v3.1 可以围绕“指标注册中心”继续推进：

1. 抽象 `Metric Registry`，把指标公式、字段依赖、指标类型、格式化方式、越高越好/越低越好、推荐图表集中管理。
2. 补充更多电商广告指标：CVR、CPA、CPL、CTR、CVR、AOV、退款率、复购率、CAC、LTV、LTV/CAC。
3. 增加“未支持指标识别”机制：用户问到未注册指标时，系统说明缺少哪些字段。
4. 将 RAG 知识卡与指标注册中心关联，避免知识库知道指标但系统不能算。
5. 增加指标级测试用例，验证每个指标的公式、图表和回答是否一致。

## 面试表达建议

可以这样讲：

> v2 阶段我接入了 DeepSeek API 和 RAG，让 Copilot 能基于电商广告知识库组织分析回答。但测试中发现，仅靠知识库是不够的。比如用户问 CPC，LLM 知道 CPC 是广告消耗除以点击量，但如果系统没有把 CPC 注册为可计算指标，图表证据和回答就会脱节。所以我把项目推进到 v3.0，开始建设指标系统，把指标公式、字段依赖、图表证据和 RAG 知识打通，保证 AI 的回答是基于真实可追溯数据，而不是只靠模型语言能力。
